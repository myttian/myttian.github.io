## 栈

- **栈是空的时候**，`SS:SP`指向最高地址单元的下一个单元，`sp+2`
  - 推理：栈中有1个元素时，`ss=1000h,sp=000eh`, 栈为空，相当于pop唯一的元素，`sp=sp+2, sp=e+2=10`
- **重点**： 入栈出栈==以字为单位操作== 
  - 函数变量放在栈中，出了函数，局部变量就失效
  - push时sp先减2,pop时先取数据再加2
    - `push:  sp-2，再放入数据` 
    - `pop： 先取出数据，再sp+2` 
- 用栈临时保存数据
  - 调用函数时，要把当前寄存器保存起来，调用完后再恢复当前寄存器数据

## 数据处理的2个基本问题

### 数据位置

- 数据在3个位置: cpu内部、内存、端口
  - 立即数
  - 寄存器
  - 段地址SA:偏移地址EA

- ==立即数==：数据在`cpu指令缓冲器`中


### 数据长度

==数据长度==：1.寄存器名指明要处理的数据长度(ax,al)  2.`mov word ptr ds:[0],1`指明   3.其它方法 `push [100h]`



用`[bx+idata+si]`的方式来访问结构体中的数据

- 用`bx`定位整个结构体，用`idata`定位结构体中的某一个数据项，用 `si` 定位数组项中的每个元素
- 为此，汇编语言提供了更为贴切的书写方式。如：`[bx].idata`、`[bx].idata[si]`

- ==被除数==：默认放在`ax(16b)` 或 `dx和ax(32b)`
- ==除数==： 8或16位
- ==商==： 8位放在 `al`， 16位放在 `ax`
- ==余数==：8位放在 `ah`， 16位放在 `dx`

==dup== 使用格式： `db 重复次数 dup (要重复的字节型数据)`    例：`db 200 dup (0)`

## 转移指令

> 1. 根据位移进行转移的jmp指令： `short near`
> 2. 转移的目的地址在指令中的jmp指令 :  `far`
> 3. 转移的地址在寄存器中的jmp指令 : `jump bx`  寄存器里放的是 `IP` 的值
> 4. 转移的地址在内存中的jmp指令:  `jmp word ptr 内存单元地址`,  `jmp dword ptr 内存单元地址`

`offset` : **获取标号或变量的偏移地址**;   相对于`代码段起始地址`的偏移量 

**跳转距离**

- ==段间==转移: `远转移`
  - 转移的==目的地址在指令中==的jmp指令, 因为debug中能看到 `jmp obbd:010b` 
  - 给的是==目标地址==: `段：偏移地址`
  - **同时修改cs和ip**    `jmp far ptr 标号`
- 段内==短转移== : `2^8` 一个字节, `-128~127`,   8位位移
  - 机器码给的是==偏移地址==,        `（IP）=（IP）＋8位位移量` , 等号右边的ip是 jump指令的下一条指令地址
    - 即 ”跳转目的地的指令的偏移地址(0008) = `jmp下一条指令的偏移地址`(0005) + jmp机器码包含的”03“偏移量“。
  - `JMP SHORT 转移地址标号` 
  - **只修改ip的值**，ip的修改范围为-128~127(负数跳转方向是jmp指令之前，否则是之后)，**8位的位移** 
  - 标号处`inc ax`偏移地址是0008，jmp就是0008； 机器码中确没有0008
  - `补码`是为了方便负数计算
- 段内==近转移==    16位位移     `（IP）=（IP）＋16位位移量`
  - `jmp near ptr 标号` ;**只修改ip的值**，ip的修改范围为-32768~32767，**16位的位移**

转移地址在**寄存器**的jump指令:

- 寄存器里放的是 `IP` 的值, `jump bx` 
- 同时修改cs、ip： `jmp 2ae3:3`
- 仅修改ip： `jmp ax`

转移地址在**内存**的jump指令: 两种格式

- ==段内转移== `jmp word ptr 内存单元地址`
  - 内存单元给的是`转移的目的`偏移地址
- ==段间转移== `jmp dword ptr 内存单元地址`
  - 双字，内存高地址是转移目的的段地址，低地址是偏移地址



==条件跳转==**jcxz** 和 loop循环

- ==jcxz==, 当(cx)`=0,就跳转`到标号处执行， 不为0就不跳, `jump cx zero`
- ==loop==, (cx)=0,不跳转，和 `jcxz`相反
- 条件转移指令都是短转移, `2^8` 一个字节, `-128~127`,   8位位移

### 根据位移进行转移的意义

- 机器码不包含目标地址，而是包含偏移地址
- 这样设计，方便程序段在内存中浮动装配

## 标志寄存器

标志寄存器16位, `0、2、4、6、7、8、9、10、11位有意义`

- 零标志位： 结果为0， ZF=1，  `在第6位`
- 奇偶：指令执行后，结果中`1的个数为偶数`，则PF=1
- `符号`：结果为负，SF=1,  结果是不是负数   `在第7位`
  - 用补码表示有符号数
- `进位标志位`：CF
  - 用标志寄存器的第0位作为进位时假想位
  - **无符号数运算时**，用进位标志
    - 2数相加时，==进位==记录到CF位
    - ==借位==时，也记录到CF位

- `溢出`： OF  `在第11位`
  - **有符号数运算时**，用溢出标志

### ==adc、sbb==、cmp

- adc （add carry） :==带进位加法==
  - 低位相加出现进位后不会舍弃，在第二步高位相加 :     `add ax,bx`和 `add al,bl   adc ah,bh` 有相同的结果
  - 加法可以分2步进行: 1、低位相加  2、高位相加再加上低位相加产生的进位值

- sbb （sub borrow） : `subtraction`  ==带借位减法==

- cmp: `相当于减法指令，只是不保存结果` ,==仅影响标志位==
  - `cmp ax,ax`, 做 `(ax)-(ax)`运算，结果为0，但并不在ax中保存，仅影响标志位

小结： `rep movsb` ，  如何改变`DF`的值：  cld、std

串传送指令 : 在==两个存储单元之间进行数据传送==, `DF`控制每次操作后 `si、di`增减

- 如`MOVSB、‌MOVSW`或MOVS dest,src，‌用于完成两个存储单元之间的数据传送。‌
  - `((es)x16+(di))=((ds)x16+(si))` :  `段地址ds，偏移地址si`的内存单元数据，放入 `es:di`    
  - movsb: `move string byte` ，传送一个字节
  - `rep movsb` : rep作用是根据`cx`的值，重复执行后面的串传送指令
- 这些指令==可以处理字节或字的数据==，‌并且`能够在源位置和目标位置之间进行复制操作`，‌而源操作数的内容保持不变。‌
  - 具体来说，‌MOVSB指令将`DS所指向的存储单元`中的一个字节`传送到ES所指向的存储单元`，‌如果DF（‌Direction Flag）‌设置为0，‌则在传送后SI和DI都增加1；‌如果DF设置为1，‌则在传送后SI和DI都减少1。‌
  - 类似地，‌==MOVSW指令处理字数据==，‌并根据DF的值决定传送后地址的增减。‌
  - 此外，‌串传送指令的使用通常与重复前缀（‌如`Rep`）‌结合，‌以简化程序并提高运行速度。‌例如，‌当需要==将大量数据从一个地址范围传送到另一个地址范围时==，‌可以使用`REP前缀`与MOVSB指令结合，‌实现无条件重复传送操作，‌直到CX寄存器中的重复次数用完为止。‌
  - 如何改变`DF`的值：  cld: `clear df`    std: `set df`

# 中断

- ==中断源==： 引起中断的原因，分为`硬件和软件中断`
  - 为什么是256个中断源： 因为`索引用的中断类型码是8位`，$2^8=256$ 
- 硬件中断
  - `外部中断`: 外设发出的中断请求，利用中断控制器可屏蔽
  - `内部中断`：硬件或运算出错引起的中断，不可屏蔽
- 软件中断
- ==中断处理程序==： 根据中断向量表里的，段地址和偏移地址，找到中断处理程序
  - 8位中断类型码`(索引)`，不够存放段地址和偏移地址，引入 ==中断向量表== ,它里面存中断处理程序的地址
  - 中断向量表==1024==字节： 一个物理地址要4个字节存放，段地址：偏移地址都是16位； 2+2字节； 占用`4 × 256`字节, 一段安全的空间里讲的 `0:200~0:300`，本来是要存中断向量表
  - 中断向量表： `0:0 ~ 0:03ff` ,共==1024==字节

- ==中断过程==：用`中断类型码，找到中断向量，并用它设置cs和ip`，由cpu硬件自动完成，cpu完成这个工作的过程称为中断过程
  - 取得中断类型码
  - 保存当前状态：标志寄存器值，`TF、IF置0`， CS入栈、IP入栈
  - 读取中断处理程序入口地址，设置CS、IP

### 键盘处理过程

键盘芯片对键盘每个键的开关状态进行扫描，按键，开关接通，该芯片产生一个`扫描码(通码)`，说明了按键在键盘上的位置。

- 扫描码被送入端口`60h`, 松开键也产生一个`扫描码（断码）`，也送入`60h`
- 扫描码一个字节，通码第7位为`0`,断码为`1`, `10,000,000=80h`,从0位开始到第7

int9键盘中断处理流程：

1. 读取`60h`端口的扫描码
2. 若是字符键扫描码，将该扫描码和对应的ASCII码，送入内存中的`BIOS键盘缓冲区`。
   1. 若是控制键（ctrl）和切换键（caplock）扫描码，则转为==状态字节==
   2. `0040：17`单元存储键盘状态字节
3. `IF=1`，响应中断

- ==译码==： CPU根据存储器提取到的指令来决定其执行行为。在解码阶段，指令被拆解为有意义的片段，根据CPU的`指令集架构（ISA）定义将数值解译为指令`
  - 控制器`分析指令的操作性质`
  - 控制器向有关部件`发出指令所需的控制信号`
  - **流程**：送入`IR的指令，通过指令译码 翻译`，==发现是一个加法指令==，就知道指令要干什么了，然后控制电路据此产生控制信号，发到相关部件中。
- ==执行==： ==连接到==各种能够进行所需运算的==CPU部件==
  - 算数逻辑单元（ALU）执行三类计算：算数逻辑运算、计算内存引用有效地址、针对push和pop等计算栈指针的增减
  - 控制器从通用寄存器或存储器`取出操作数`
  - 控制器命令运算器对操作数进行指令规定的`运算`
  - **流程：** `ADD R0，[6]`，其中一个操作数[6]在存储器中， 地址放入MAR，通过地址总线存入存储器MAR, 然后类似取指，对应的地址内容送入MDR,因为要进行加法运算，送入ALU的Y寄存器，另一个操作数R0内容，送入X寄存器，ALU进行运算 
- ==回写==(write back)： 将指令执行的`结果写回通用寄存器或存储器`，  运算结果写入`通用寄存器 或 存储器`； 例子里 结果回写到RO寄存器中

单位时间通过内存的数据量。内存带宽通常以==每秒传输的比特数==（bits per second, bps）或字节数（bytes per second, Bps）来衡量 

1. 内存的`位宽`（Bit Width）：这是内存芯片每次可以读或写的位数。例如，64位的内存一次可以传输64位数据
2. 内存的`时钟频率`（Clock Frequency）：这是内存操作的频率，单位通常是赫兹（Hz）。例如，1 GHz意味着每秒有10亿次操作
   1. ‌‌CPU主频:  CPU内核工作的时钟频率，表示CPU内数字脉冲信号震荡的速度‌,  衡量`CPU执行指令速度`的指标。它表示CPU每秒钟能够进行的周期性操作次数
3. 每次操作的数据量：这通常与内存的位宽相关，即`每次操作传输的位数` 

==计算公式==： `内存带宽 = 内存位宽 x 时钟频率`  **$$ \text{内存带宽} = \text{内存位宽} \times \text{时钟频率} $$**

- 例如，内存芯片位宽64位，时钟频率为2 GHz，其内存带宽为 `64 bits/cycle  x  2,000,000,000 cycles/second =  1,280,000,000  bits/second`   $$ \text{内存带宽} = 64 \text{ bits/cycle} \times 2,000,000,000 \text{ cycles/second} = 1,280,000,000 \text{ bits/second} $$
- 转换为字节（Byte） : `1,280,000,000 \text{ bits}}{8} = 160,000,000 \text{ Bytes/second`    $$ \text{内存带宽} = \frac{1,280,000,000 \text{ bits}}{8} = 160,000,000 \text{ Bytes/second} $$

- CS和IP的全称分别是Code Segment（代码段寄存器）和==Instruction Pointer==（指令指针寄存器）
- CS寄存器：存放内存`代码段的入口地址`，IP寄存器用于指示`下一条指令的内存地址`。当CPU执行指令时，通过CS和IP来确定要执行的指令地址‌

**cs ip、 ss sp、 ds es ,  程序员通过改变寄存器内容实现对cpu的控制**， 

8086CPU有==**4个段寄存器**==， 提供内存单元的段地址

- - CS（code segment）、DS（data segment）、SS（stack segment）、 ES（extra segment）
    - 这些寄存器分别用于==存放当前正在运行的程序==代码所在段、‌数据段、‌堆栈段以及附加数据段的信息
    - 分别用于指令、数据、其它和堆栈
    - **DS**==指向数据段==，ES指向附加段, 存取操作数时，二者之一和一个偏移量合并, 就可==得到存储单元的物理地址==    [段寄存器的作用](https://baike.baidu.com/item/%E6%AE%B5%E5%AF%84%E5%AD%98%E5%99%A8/6616912?fr=ge_ala)  
      - 该偏移量可以是具体数值、符号地址和指针寄存器的值等之一，具体情况将由指令的寻址方式来决定
    - **CS**指向==存放汇编程序==的内存段，IP是用来存放下条待执行的指令在该段的偏移量，把它们合在一起可在该内存段内==取到下次要执行的指令==
    - **SS**指向==用于堆栈==的内存段，SP是用来指向该堆栈的栈顶，把它们合在一起可访问栈顶单元
      - 另外，当偏移量用到了指针寄存器BP，则其缺省的段寄存器也是SS，并且用BP可访问整个堆栈，不仅仅是只访问栈顶
  - IP 指令指针寄存器，偏移寄存器, 专用寄存器
  - CS和IP : 指示CPU==当前要读取指令的地址==； mov指令需要3个字节，mov传送指令

3.6 栈
    1.8086CPU提供相关的指令来以栈的方式访问内存空间
        这意味着，我们在基于8086CPU编程的时候，可以将一段内存当作栈来使用
    2.8086CPU提供入栈和出栈指令：（最基本的）
        push（入栈）
        pop（出栈）
        1.push ax：将寄存器ax中的数据送入栈中
        2.pop ax：从栈顶取出数据送入ax
        3.8086CPU的入栈和出栈操作都是以【字（16位）】为单位进行的
        4.pop和push可以在寄存器和内存之间传送数据
    3.CPU如何知道一段内存空间被当做栈使用？
        1.8086CPU中，有两个寄存器
            1.段寄存器SS：存放栈顶的段地址
            2.寄存器SP：存放栈顶的偏移地址【专用寄存器】
        2.任意时刻SS:SP指向栈顶元素，当栈为空的时候，也就不存在栈顶元素
            ss:sp也就指向栈最高地址单元的下一个单元
    4.执行push和pop的时候，如何知道哪个单元是栈顶单元？
        1.执行push ax时
            1.sp=sp-2
            2.将ax中的内容送入到ss:sp指向的内存单元
                ss:sp此时指向新栈顶
        2.执行pop ax时
            1.将ss:sp指向的内存单元的内容送入到ax中
                注意：这里取出的内容在内存中还是存在的，并没有被重置
                    下一轮push会覆盖
            2.sp=sp+2
    5.如果栈是空的，sp指向哪里？
        sp指向最高地址单元的下一个单元
3.7 栈顶超界的问题
    ss、sp只记录了栈顶的地址，依靠ss、sp可以保证在入栈和出栈时找到栈顶
    可以，如何能够保证在入栈、出栈时，栈顶不会超出栈空间？
    1.8086CPU不保证栈的操作不会越界
    2.当栈空的时候，再执行pop出栈 或者 当栈满的时候再使用push入栈
        都会发生栈顶超界问题，会操作到栈以外的数据，
        这些数据可能是其他用途的数据或者代码
        栈顶超界是危险的！！！
    3.8086CPU没有记录栈顶上下限的寄存器
3.8 栈段
    1.将一段内存当做栈段，仅仅是我们在编程时的一种安排，
    2.ss:sp指向我们定义的栈段的栈顶；
    3.当栈空时，sp指向最高地址的下一个单元
    4.思考：一个栈段最大可以设为多少？
        64KB
    5.设栈顶的变化范围是0-FFFFH，从栈空时sp=0（最高地址单元FFFFH的下一个单元0000H）
        一直压栈，直到栈满，sp=0；
        如果再次压栈，栈顶将环绕，覆盖原来栈中的内容
    6.一段内存，既可以是代码的存储空间，又可以是数据的存储空间，还可以是栈空间
        也可以是什么都属实。
        关键在于CPU中寄存器的设置，即：cs、ip、ss、sp、ds的设置
        **可以通过mov直接给sp赋值【立即数寻址】，但是不能通过mov给cs、ip、ss、ds赋值
            给cs和ip赋值需要使用jum指令
            给ss和ds赋值需要使用mov ss或ds,寄存器   ;【寄存器寻址】

最高是F，栈没有元素，栈顶指向F的下面，即F+2 = 10

### 标号

[什么是标号](https://worktile.com/kb/ask/2416311.html)	[数据标号与定址表应用](https://blog.csdn.net/weixin_30319097/article/details/101559539)	[全局标号和局部标号](https://www.cnblogs.com/liming19680104/p/17861298.html)	

标号作用： 1、标记位置  2、作为跳转目标

标号的定义通常位于指令或数据的前面，并且以冒号（:）结尾

号还可以用来定义数据的起始位置： `data_label db 1, 2, 3, 4` 

==作用域==：标号的作用域通常限于定义它的`代码块或函数内部`。这意味着在其他代码块或函数中无法直接引用该标号。这是为了避免命名冲突和混淆

==数据标号==：

- 普通的标号只能表示内存地址
- 数据标号即可表示内存地址，也可表示内存单元的长度
  - 使用数据标号可以以更加简洁的方式访问内存中的数据
  - 数据标号的格式为：只有标号名，没有冒号

==全局标号和局部标号==

- 局部标号： `标号名:目的指令` 	   **作用域是当前的子程序**  
- 全局标号： `标号名::目的指令`

==MASM中的@@==

- 用@@做标号时，可以用@F和@B来引用它
- **@F表示本条指令后的第一个@@标号**
- **@B表示本条指令前的第一个@@标号**
- 程序中可以有多个`@@`标号，但@B和@F只寻找匹配最近的一个

4.1 一个源程序从写出到执行的过程
    1.一个汇编语言程序从写出到最终执行的简要过程
        编写->编译连接->执行
    2.对源程序进行编译连接
        1.使用汇编语言编译程序（MASM.EXE）对源程序文件中的源程序进行编译，产生目标文件【.obj文件】
        2.再用连接程序（LINK.EXE）对目标文件进行连接，生成可在操作系统中直接运行的可执行文件【.EXE文件】。
    3.可执行文件包含两部分内容
        1.程序（从源程序的汇编指令翻译过来的机器码）和数据（源程序中定义的数据）
        2.相关的描述信息（比如：程序有多大、要占多少内存空间等）
    4.执行可执行文件中的程序
        1.在操作系统（如：MSDOS）中，执行可执行文件中的程序
        2.操作系统依照可执行文件中的描述信息，将可执行文件中的机器码和数据加载入内存
            并进行相关的初始化（比如：设置CS:IP指向第一条要执行的指令），然后由CPU执行程序
4.2 源程序的主要结构
    源程序由 汇编指令+伪指令+宏指令 组成
        伪指令：编译器处理
        汇编指令：编译为机器码	
    1.伪指令
        1.没有对应的机器码的指令，不能由CPU直接执行
        2.伪指令是由编译器来执行的指令，编译器根据伪指令来进行相关的编译工作
    2.segment和ends【定义一个段】
        1.segment和ends是一对成对使用的伪指令
        2.编写汇编程序【必须】使用到的指令
        3.segment和ends的功能是定义一个段
            segment：说明一个段开始
            ends：说明一个段结束
        4.一个段必须有一个名称来标识，使用格式为
            段名 segment
            段名 ends
        5.一个汇编程序由多个段组成
            这些段用来存放【代码、数据、或当作栈空间】来使用
            一个有意义的汇编程序至少要有一个段，这个段用来存放代码。
    3.end【真正的没了】
        1.end是一个汇编程序的结束标记
        2.编译器在编译汇编程序的过程中，如果碰到了伪指令end，就结束对源程序的编译
        3.如果程序写完了，要在结尾处加上伪指令end
            否则，编译器无法知道程序在何处结束
        4.【切记】不要把end和ends搞混了
            end：汇编程序的结束标记
            ends：与segment成对出现
    4.assume【寄存器和段的关联假设】
        1.它假设某一段寄存器和程序中的某一个用segment...ends定义的段相关联
        2.通过assume说明这种关联，在需要的情况下，
            编译程序可以将段寄存器和某一具体的段相联系
    5.程序和源程序
        1.我们将源程序文件中的所有内容称为【源程序】
        2.将源程序中最终由计算机执行处理的指令或数据称为【程序】
        3.程序最先以汇编指令的形式，存储在源程序中
            然后经过编译、连接后转变为机器码，存储在可执行文件中
    6.标号，标号与段名称有所区别
        1.一个标号指代了一个地址，即是段名称。
        2.段名称 放在segment的前面，作为一个段的名称
            这个段的名称最终将被汇编、连接程序处理为一个段的段地址
    7.DOS中的程序运行
        1.DOS是一个单任务操作系统
        2.一个程序结束后，将CPU的控制权交还给是他得以运行的程序
            我们称这个过程为：程序返回
    8.程序返回

        int 21H      ;【中断机制】是DOS最伟大的机制,Windows系统上是【消息机制】

    10.语法错误和逻辑错误
        1.语法错误

    连接使用的程序：link.exe
    简化方式进行汇编和连接的程序：ml.exe
4.4 汇编和连接的作用
    连接的作用
    1.当源程序很大时，可以将他们分成多个源程序文件夹编译
        每个源程序编译成为目标文件后，再用连接程序将它们连接在一起，
        生成一个可执行文件
    2.程序中调用了某个库文件中的子程序，需要将这个库文件和该程序生成的目标文件连接到一起
        生成一个可执行文件
    3.一个源程序编译后，得到了存有机器码的目标文件，目标文件中的有些内容还不能直接
        用来生成可执行文件，连接程序将这些内容处理为最终的可执行信息。
      所以在只有一个源程序文件，而又不需要调用某个库中的子程序的情况下，也必须用
        连接程序对目标文件进行处理，生成可执行文件
4.5 可执行文件中的程序装入内存并运行的原理
    1.在DOS中，可执行文件中的程序P1若要运行，必须有一个正在运行的程序P2
        将P1从可执行文件中加载入内存，将CPU的控制权交给P1，P1才能得以运行
    2.当P1运行完毕后，应该将CPU的控制权交还给使他得以运行的程序
    3.操作系统的外壳
        1.操作系统是由多个功能模块组成的庞大、复杂的软件系统
            任何通用的操作系统，都需要提供一个称为shell（外壳）的程序，
            用户（操作人员）使用这个程序来操作计算机系统工作
        2.DOS中有一个程序command.com，这个程序在DOS中称为命令解释器
            也就是DOS系统的shell
    4.执行可执行文件1.exe时，
      （1）什么程序将CPU的控制权交给了1.exe？
      （2）将程序1.exe加载入内存后，如何使程序得以运行？
      （3）1.exe程序运行结束后，返回到了哪里？
        1.在DOS中直接执行1.exe时，是正在运行的cmd.exe将1.exe中的程序加载入内存
        2.cmd.exe设置CPU的CS:IP指向程序的第一条指令（即，程序的入口）
            从而使程序得以运行
        3.程序运行结束后，返回cmd.exe中，CPU继续运行cmd.exe

## gcc编译流程

[gcc/g++编译流程](https://baike.baidu.com/item/g%2B%2B/8324824?fr=ge_ala) 

```sh
gcc/g++编译流程

# 预处理，生成.i的文件[预处理器cpp]
# 将预处理后的文件转换成汇编语言，生成文件.s[编译器egcs]
# 由汇编变为目标代码（机器代码）生成.o的文件[汇编器as]
# 连接目标代码，生成可执行程序[链接器ld]
```

若干个源文件经过编译之后生成若干个==目标文件==。经过[链接器](https://so.csdn.net/so/search?q=链接器&spm=1001.2101.3001.7020)==把目标文件和所需要的库函数==链接起来，生成可执行程序

```sh
# 预处理:	展开头文件/宏替换/去掉注释/条件编译	（  test.i  main .i  ）
# 编译:	检查语法，生成汇编					 （  test.s  main.s ）
# 汇编:	汇编代码转换机器码   				 (  test.o main.o  )
# 链接:	链接到一起生成可执行程序				a.out
```

- 在C++编译过程中，最后一步需要进行链接，如果程序依赖于外部库，**链接器将库文件与程序的目标文件结合起来**。
  - `静态链接`: **库的代码被复制到最终的可执行文件中** 
    - A和B依赖**静态链接库 static library**，A和B在运行时，内存中会有多份static library
  - `动态链接`: **程序在运行时加载依赖的库** 
    - A和B依赖**动态链接库 shared library**，A和B在运行时，内存中只有一份 shared library（shared：共享）
    - 动态链接库加载后，**在内存中仅保存一份拷贝**，多个程序依赖它时，**不会重复加载和拷贝**，`节省内存空间`
