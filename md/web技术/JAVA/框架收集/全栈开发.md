## 后端开发技术

[后端开发技术有哪些_百度搜索](https://www.baidu.com/s?ie=UTF-8&wd=%E5%90%8E%E7%AB%AF%E5%BC%80%E5%8F%91%E6%8A%80%E6%9C%AF%E6%9C%89%E5%93%AA%E4%BA%9B)  

后端开发技术覆盖编程语言、框架、数据库、中间件、部署运维等多个层面，下面按类别梳理主流选项。

### 编程语言

- Java：企业级开发首选，生态完善，适合高并发、高稳定性场景（如电商、金融）。
- Python：语法简洁、开发效率高，适合快速迭代，常用于数据驱动或AI结合项目。
- Go：性能好、原生支持并发，适合微服务和云原生应用。
- JavaScript/TypeScript（Node.js）：前后端语言统一，适合I/O密集型应用（如实时聊天、API服务）。
- PHP：传统Web开发语言，适合内容管理系统（如WordPress）。
- `C#`（.NET）：微软生态，适合Windows服务或企业级应用。
- Ruby（Ruby on Rails）：适合快速原型开发，近年热度下降。
- Rust：内存安全、性能高，适合对安全性要求极高的系统（如区块链）。

### 开发框架

- Java：Spring Boot（REST API、微服务）、Spring MVC、Jakarta EE。
- Python：Django（全功能）、Flask（轻量级）。
- Node.js：Express.js（极简）、NestJS（企业级）。
- Go：Gin、Echo。
- PHP：Laravel、Symfony。

### 数据库

- 关系型数据库（RDBMS）：MySQL、PostgreSQL（开源）、Oracle、SQL Server（商业），适合结构化数据、事务一致性要求高的场景。
- NoSQL数据库：
  - 文档型：MongoDB、Couchbase
  - 键值型：Redis（缓存/会话）、Memcached
  - 列存储：Cassandra（大数据场景）
  - 图数据库：Neo4j（社交网络、关联数据）
- 数据库管理：连接池（HikariCP）、分库分表（ShardingSphere）、读写分离。

### API与通信

- RESTful API：主流设计风格，基于HTTP方法操作资源，简单灵活。
- GraphQL：客户端精确获取所需数据，减少网络请求，适合复杂查询。
- gRPC：Google开源的高性能RPC框架，基于HTTP/2和Protocol Buffers，适合微服务内部通信。
- WebSocket：实时双向通信，适合聊天、推送场景。

### 中间件与基础设施

- 缓存：Redis（最主流）、Memcached，用于减轻数据库压力、提升响应速度。
- 消息队列：Kafka（高吞吐）、RabbitMQ（易用）、RocketMQ（阿里开源），用于异步任务和削峰填谷。
- 搜索引擎：Elasticsearch（全文检索）、Solr。
- 对象存储：AWS S3、阿里云OSS、MinIO（自建）。
- API网关：Kong、Netflix Zuul，用于统一请求入口、鉴权和限流。

### 部署与运维

- 容器化：Docker（打包应用）、Kubernetes/K8s（集群管理）。
- 云服务：公有云（AWS、阿里云、腾讯云）、私有云（OpenStack、VMware）。
- CI/CD：Jenkins、GitLab CI、GitHub Actions，实现自动化测试与部署。
- 监控与日志：Prometheus（指标监控）、Grafana（可视化）、ELK Stack（日志分析）。

### 安全与性能

- 认证授权：OAuth2.0、JWT、SSO单点登录。
- 数据加密：HTTPS（TLS）、数据库字段加密。
- 防御攻击：WAF（Web应用防火墙）、SQL注入/XSS防护。
- 性能优化：负载均衡（Nginx、HAProxy）、CDN加速、数据库索引优化、缓存策略。

### 选型建议

- 初创/快速迭代：Python（Django）+ PostgreSQL + Docker + AWS。
- 企业级复杂系统：Java（Spring Boot）+ MySQL + Kubernetes + Kafka。
- 实时应用：Node.js + MongoDB + Redis + WebSocket。
- 云原生微服务：Go + gRPC + Istio + Prometheus。

> 实际选型要结合团队技术栈和项目需求灵活组合，避免过度设计，优先考虑可维护性和扩展性。

## 前端开发技术汇总

前端技术栈这些年从"会三件套就能干活"演变成了分工细致的工程体系。下面按**从底层到上层、从开发到上线**的顺序梳理一遍，你可以把它当作知识地图或查漏补缺的清单。

---

### 一、地基：必须扎实的部分

| 类别 | 核心技术           | 说明                                                        |
| ---- | ------------------ | ----------------------------------------------------------- |
| 结构 | HTML5              | 语义化标签、表单、多媒体、Canvas/SVG、Web Components        |
| 样式 | CSS3               | 盒模型、Flex、Grid、动画、过渡、媒体查询、层叠与 BFC        |
| 语言 | JavaScript（ES6+） | 原型链、闭包、this、事件循环、Promise/async、模块化、装饰器 |
| 类型 | TypeScript         | 类型系统、泛型、接口、类型推断、工具类型、声明文件          |
| 网络 | HTTP / 浏览器原理  | 请求响应、缓存策略、跨域、同源策略、渲染流程、重排重绘      |

这一层是**唯一不会过时的部分**。框架每三五年换一轮，但事件循环、原型链、CSS 层叠上下文、浏览器渲染管线十年没变过。面试和长期竞争力基本都压在这里。

---

### 二、主流框架（三选一深入，其余了解）

**React**

- 核心：JSX、组件、Props/State、Hooks（useState、useEffect、useMemo、useRef、useContext）
- 进阶：Concurrent Mode、Suspense、Server Components（RSC）、Actions、Transitions
- 生态：Next.js（全栈框架，App Router）、React Router、TanStack Query、Zustand/Jotai
- 特点：生态最大、灵活度高、心智负担集中在 Hooks 规则上

**Vue**

- 核心：模板语法、响应式（Proxy）、组合式 API（ref、reactive、computed、watch）
- 进阶：Teleport、Suspense、KeepAlive、自定义指令、插件机制
- 生态：Vue Router、Pinia、Nuxt、Element Plus / Ant Design Vue / Naive UI
- 特点：上手曲线平缓、中文资料丰富、国内企业使用率高

**Angular**

- 核心：TypeScript 强绑定、依赖注入、模块、装饰器、RxJS
- 特点：大而全、约定多、适合大型团队长期项目，国内使用面相对窄

**其他值得关注的**

- Svelte / SvelteKit：编译时框架，无虚拟 DOM，语法简洁
- Solid.js：细粒度响应式，性能优秀
- Qwik：可恢复性（Resumability），极致首屏
- 小程序 / Taro / uni-app：国内跨端必备

---

### 三、样式与 UI

**CSS 工程化方案**

- 预处理器：Sass / Less（变量、嵌套、混入、模块化）
- 原子化 CSS：Tailwind CSS（当前主流）、UnoCSS
- CSS Modules：局部作用域，避免命名冲突
- 现代 CSS：自定义属性（CSS 变量）、`:has()`、容器查询、嵌套语法、`@layer`

**组件库**

- React：Ant Design、MUI、Chakra UI、shadcn/ui（复制式，非依赖式）
- Vue：Element Plus、Ant Design Vue、Naive UI、Vuetify
- 跨框架：Bootstrap、Bulma、Material Web Components

**图表与可视化**

- ECharts（国内首选）、AntV（G2/G6/X6）、D3.js（底层定制）、Three.js / Babylon.js（3D）、Konva / PixiJS（Canvas 2D）

---

### 四、构建与工程化

**构建工具**

- Vite：当前默认选择，基于原生 ESM + esbuild，冷启动快
- Webpack：老牌，配置复杂但生态最全，老项目仍在大量使用
- Rollup：库打包首选
- esbuild / SWC / Turbopack：Go/Rust 编写，追求极致速度
- Babel：JS 转译（现在多被 SWC 替代）

**包管理与规范**

- npm / pnpm / yarn（pnpm 因磁盘占用与严格依赖结构成为新宠）
- Monorepo：pnpm workspace、Turborepo、Nx、Lerna
- Node.js 与 npm 脚本、nvm 版本管理

**代码质量**

- ESLint（v9 起扁平配置）、Prettier、Stylelint
- Husky + lint-staged + commitlint：提交前校验与规范提交信息
- EditorConfig、TypeScript 严格模式配置

**CI/CD 与部署**

- GitHub Actions、GitLab CI、Jenkins
- 静态托管：Vercel、Netlify、Cloudflare Pages、阿里云 OSS + CDN
- Nginx 反向代理、Docker 容器化部署前端产物

---

### 五、数据与状态

**服务端数据管理**（这层比"全局状态"更重要）

- TanStack Query（React Query）：请求缓存、重试、失效、乐观更新
- SWR：轻量版同类方案
- Axios / Fetch / ky：HTTP 客户端，配合拦截器做统一鉴权与错误处理

**客户端状态管理**

- 轻量：Zustand、Jotai、Recoil、Pinia（Vue）
- 传统：Redux Toolkit（不再推荐裸 Redux）、MobX
- 原则：能不放全局就不放全局，服务端数据交给 Query 类工具，客户端只存 UI 状态

**本地存储**

- localStorage / sessionStorage、IndexedDB（idb 封装）、Cookie、Cache API

### 七、性能与体验优化

**加载性能**

- 代码分割与懒加载（动态 import、路由级分包）
- 资源优化：图片格式（WebP/AVIF）、懒加载、雪碧图、字体子集化
- 缓存策略：HTML 不缓存、带 hash 的静态资源强缓存
- CDN、HTTP/2、预加载 preload / 预取 prefetch
- SSR / SSG / ISR：Next.js、Nuxt 提供的首屏与 SEO 方案

**运行时性能**

- 减少重排重绘、合成层优化、`transform`/`opacity` 做动画
- 虚拟列表（react-window、vue-virtual-scroller）处理长列表
- Web Worker 处理计算密集任务、防抖节流、`requestAnimationFrame`
- React：memo、useMemo、useCallback、避免不必要渲染
- 性能指标：LCP、INP、CLS、FCP、TTFB（Core Web Vitals）

**安全**

- XSS 防护（转义、CSP）、CSRF（Token、SameSite Cookie）
- 依赖安全（npm audit、锁文件）、敏感信息不落前端、接口权限后端校验

**可访问性与国际化**

- ARIA 属性、语义化、键盘可达、对比度
- i18n：react-i18next、vue-i18n，配合语言包按需加载

---

### 八、跨端与延伸方向

- **移动端**：React Native、Flutter（Dart）、uni-app、Taro、鸿蒙 ArkTS
- **桌面端**：Electron、Tauri（Rust 后端，体积更小）
- **服务端延伸**：Node.js + Express/Koa/NestJS、BFF 层、Serverless
- **低代码 / 可视化搭建**：表单设计器、页面搭建平台，国内需求旺盛
- **AI 前端**：大模型对话界面、流式响应（SSE）、RAG 检索展示、AI 辅助编码工具

---

### 九、给不同阶段的学习建议

**入门（0–1 年）**
把 HTML/CSS/JS 打牢，能手写布局、理解异步、做出完整页面。选一个框架（国内建议 Vue，海外/大厂建议 React）跟着官方教程做一个 CRUD 项目。此阶段**不要**追新工具。

**进阶（1–3 年）**
补 TypeScript、Git 协作、HTTP 与浏览器原理、构建工具配置、性能优化实战。开始读框架源码的关键部分（响应式系统、diff 算法、事件机制），能定位并解决线上问题。

**深入（3 年以上）**
工程化体系建设（组件库、脚手架、CI/CD、监控告警）、跨端或全栈能力、架构设计与技术选型、带人与评审。此时竞争力来自"能定义问题"而非"会用工具"。

---

### 十、一句话总结趋势

当前前端的几个明确方向：**构建工具 Rust/Go 化提速**、**样式原子化（Tailwind 主导）**、**服务端组件与全栈框架融合（Next.js/Nuxt 成为默认入口）**、**状态管理轻量化**、**AI 深度嵌入开发与产品形态**。技术名词会持续增加，但底层能力（语言、浏览器、网络、工程思维）才是抗周期的部分。

## 脚手架是什么

[编程中的脚手架是什么](https://docs.pingcode.com/ask/294706.html)   [编程脚手架是什么_百度搜索](https://www.baidu.com/s?ie=UTF-8&wd=%E7%BC%96%E7%A8%8B%E8%84%9A%E6%89%8B%E6%9E%B6%E6%98%AF%E4%BB%80%E4%B9%88)  

编程脚手架（Scaffolding）就是帮你==自动生成项目基础结构==的工具，像盖房子前搭的临时支架，先搭好骨架和标准配置，你直接填业务逻辑即可。

> 指项目模板工具、**快速项目启动方法**、**项目结构生成器**
>
> - 用于帮助自动化创建和维护标准化编程项目结构。通过使用脚手架，开发者可以快速构建出项目基础框架，省却重复性的初始设置工作，让开发者专注于业务逻辑的编写。
> - 脚手架通常包括了文件目录结构、基础代码文件、配置文件以及常用库的引用，它的核心价值在于提高开发效率、促进项目的规范化和减少错误

### 它解决什么问题

- 省掉重复劳动：不用每次手动建目录、配路由、写入口文件，一条命令搞定。
- 统一项目规范：团队用同一脚手架，目录结构、代码风格、依赖版本保持一致，新人接手不迷路。
- 屏蔽底层细节：如数据库连接、日志、鉴权等通用部分预先配好，你专注业务功能。

### 常见的脚手架

1. 前端：`Vue CLI、Create React App`，快速搭好前端工程。
2. 后端：Spring Boot 自动配置项目骨架和常用组件；Maven 管理依赖和构建。
3. 全栈/微服务：`Dropwizard` 集成 Jetty、Jersey、Jackson 等，快速提供 RESTful 服务。
4. 代码生成：Go 生态的 goctl，根据定义生成 API 服务代码。

### 脚手架通常包含什么

一个标准脚手架会生成==入口文件、配置文件（环境变量、数据库连接）、数据层（模型/实体）、业务逻辑层（服务）、接口层（路由/控制器）、中间件、工具函数、测试目录和依赖声明==。

> 简单理解：脚手架是“方案的封装”——把团队沉淀的最佳实践固化下来，让你不重复造轮子。

脚手架能帮你快速搭好项目骨架，要不要继续看看前端和后端脚手架有何区别?或者脚手架和模板有什么不同?

Java脚手架主要分两类：一类是开箱即用的后台管理快速开发脚手架，另一类是用于快速生成项目骨架的工程化脚手架。国内最主流的Java脚手架是RuoYi（若依）、JeecgBoot、eladmin、Pig和yudao（芋道）。

### 主流开源脚手架

1. RuoYi（若依）：普及度最高的国产脚手架，有单体、前后端分离、微服务多个版本。基于Spring Boot + Spring Security + MyBatis，内置RBAC权限、代码生成器、定时任务，适合快速交付内部管理系统、外包项目和毕设。

2. JeecgBoot（积木）：低代码开发平台，支持在线表单、积木报表、流程设计器、大屏设计。适合表单报表密集、需求变化快的企业系统，但学习曲线比RuoYi陡。

3. eladmin：轻量级单体脚手架，基于Spring Boot + Spring Security + JPA，代码简洁规范、依赖少，适合中小团队、个人项目，也适合读源码学习权限认证流程。

4. Pig：基于Spring Cloud Alibaba的微服务脚手架，集成Nacos、Gateway、OAuth2 + JWT认证，适合中大型微服务项目，但本地启动内存占用大，需要团队有微服务基础。

5. yudao（芋道）：单体版和微服务版（yudao-cloud）都有，开源了多租户、数据权限、支付、工作流、SaaS能力等模块，适合中大型项目或SaaS方向，功能多但学习成本较高。

6. Guns：老牌企业级脚手架，工程规范性强、分层清晰，支持Vue3和React前端，适合注重长期维护和规范化开发的团队。

### 工程化脚手架

如果只是需要快速生成项目骨架而非完整后台系统，可以参考：

- Spring Initializr（start.spring.io）：官方提供的Spring Boot项目生成器，在线选择依赖即可生成基础工程。
- Maven Archetype：通过`mvn archetype:generate`从模板生成项目结构，适合公司内部沉淀统一工程规范。
- COLA：阿里开源的架构脚手架，主要提供清晰的面向对象和分层架构约束，不内置业务功能，适合追求规范架构的团队。

### 选型建议

- 单体后台、快速交付：首选RuoYi，资料多、社区大、代码生成器成熟。
- 表单报表密集、低代码需求：JeecgBoot更合适。
- 想学源码、做轻量项目：eladmin代码干净，适合阅读和二次开发。
- 确定走微服务：Pig或yudao-cloud，但建议先在单体架构上验证业务再拆分。
- 商用注意：部分项目开源版和商业版功能有边界，商用前确认License协议。

选型时除了看功能，还可以了解RuoYi和JeecgBoot的代码量差异大吗?或者Pig和yudao的微服务架构有何区别?
