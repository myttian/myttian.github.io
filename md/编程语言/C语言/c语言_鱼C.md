> **构建和编译是软件开发过程中的两个不同阶段，它们在功能与目的、执行环境与依赖、执行频率与阶段、涉及的工具与资源以及输出与结果方面存在差异。**‌
>
> - ‌**功能与目的**‌：==构建是将源代码转化为可执行代码的过程==，它包括编译、链接、打包等一系列步骤，可能涉及测试、部署等。编译则是构建过程中的一个阶段，专门负责将人类可读的源代码转换成机器可执行的代码或中间代码。
> - ‌**执行环境与依赖**‌：构建通常涉及复杂的依赖管理和环境配置，不仅包括编译，还可能包括测试、压缩、优化等步骤。编译只依赖于源代码和编译器，将源代码转换为目标代码或字节码。
> - ‌**执行频率与阶段**‌：构建在开发过程中可能频繁执行，涉及的阶段从开发到测试再到部署都可能涉及。编译通常作为构建过程中的一个步骤，每次构建都会执行。
> - ‌**涉及的工具与资源**‌：构建工具通常更为复杂，例如Jenkins、TeamCity等，可能涉及源代码管理、依赖管理、任务调度等。编译工具相对简单，例如GCC、javac等，主要负责源代码的转换。
> - ‌**输出与结果**‌：构建的输出是一个完整的可部署或可执行的软件产品，包括编译后的代码、资源文件、配置等。编译的输出是中间代码或机器代码，通常需要链接等步骤才能成为可执行文件。
>
> 综上所述，‌**编译**‌主要是将源代码转换为机器代码的过程，而‌**构建**‌则是一个更广泛的过程，包括编译在内的多个阶段，旨在生成一个可部署或可执行的软件产品。两者在软件开发过程中共同作用，以确保软件的质量、兼容性和可维护性‌

**java是解释型语言**， 不直接编译成机器码，而是==将源代码转换为中间代码==（字节码），发送给解释器，由解释器逐句翻译给cpu执行；  好处是可以实现跨平台; 每次都要翻译，所有效率低

- 编译型：做好菜再开吃；   解释型：火锅，想吃什么下什么料

源代码经过**编译**得到汇编代码，汇编代码*经过**汇编**得到*机器代码

- 把 `预处理+编译+汇编+连接` 简称为“编译+连接”，甚至直接称为“编译” 
- 汇编是从汇编语言到机器码的过程
- 编译是 `源代码->词法分析->语法分析->中间代码生成和优化->汇编代码->机器码` 的过程，有一些语言是解释执行，就转为对应虚拟机的字节码。  

1. **预编译：** `Add.h` 和`Test.c` 头文件和源文件     [好：汇编和编译具体指什么-](https://www.zhihu.com/question/388069555)    [C++中预处理、编译、汇编、链接的区别](https://blog.csdn.net/qq_40287633/article/details/128006176?spm=1001.2101.3001.6661.1&depth_1-utm_source=distribute.pc_relevant_t0.none-task-blog-2%7Edefault%7EBlogCommendFromBaidu%7EPaidSort-1-128006176-blog-123750439.235%5Ev43%5Epc_blog_bottom_relevance_base5) 
   1. 预编译的指令`gcc Test.c -E -o Test.i`，将`Test.c`预编译为 ==Test.i==    也可以 `gcc  Test.c && ./Test.out`
   2. 编译时会将包含的[头文件](https://www.zhihu.com/search?q=头文件&search_source=Entity&hybrid_search_source=Entity&hybrid_search_extra={"sourceType"%3A"answer"%2C"sourceId"%3A3495132276})和`define`等替换拓展
   3. 注释会被删除。注释毕竟是给人看的，编译器不需要
2. **编译：**  `gcc -S Test.i -o Test.s` 将`Test.i`编译为 ==Test.s==  ；    
   1. 代码被转化成了[汇编语言](https://www.zhihu.com/search?q=汇编语言&search_source=Entity&hybrid_search_source=Entity&hybrid_search_extra={"sourceType"%3A"answer"%2C"sourceId"%3A3495132276})，其实还进行了以下过程： 词法分析、语法分析、语义分析、中间代码生成；   
   2. 要牢记住这个步骤 `符号汇总` 。将程序中出现的`函数汇总`起来，供下一步汇编时形成符号表
3. **汇编： ** 将汇编代码转化为机器码， `gcc -c Test.s -o Test.o`  ==Test.o== 
   1. 将上一个过程汇总的符号 `形成符号表`; 符号表包含的是 **函数名以及函数的地址** 
4. **链接：** 
   1. 解决一个项目多文件，多模块==相互之间调用==的问题，将这些模块之间和文件之间连接起来
   2. 汇编过程中两个文件各生成了一个==符号表==包含着函数的名称和地址，链接时把这两个符号表合成一个，共享一个符号表，编译器会将地址无效的去除掉保留有效的
   3. 编译是将[源代码](https://www.zhihu.com/search?q=源代码&search_source=Entity&hybrid_search_source=Entity&hybrid_search_extra={"sourceType"%3A"answer"%2C"sourceId"%3A3495132276})转换为目标代码(机器语言)的过程，**目标代码**通常以对象文件的形式存在。**链接**是==将多个对象文件和库文件结合在一起==，生成一个可执行程序的过程
5. ==cl表示visual studio的编译器，gcc表示linux下的编译器==

> - 大多数现代编程语言中，当我们谈论变量时，我们主要关注的是它们存储的值，而不是它们在内存中的地址。然而，有些语言（如C和C++）允许程序员直接操作内存地址，通过指针来实现。
> - 在底层，变量通常是通过内存地址来引用的。内存地址是计算机内存中每个存储单元的唯一标识符, 我们很少直接处理内存地址，因为这样做既复杂又容易出错。理解变量在内存中有一个位置（即地址）是很重要的，特别是当我们讨论指针、引用和内存管理时
> - 在其他语言中，如Java、Python等，虽然程序员不直接操作内存地址，但变量背后的机制仍然涉及到内存地址。例如，在Java中，对象是通过引用来传递的，这些引用在底层可以看作是对象的内存地址的抽象。但是，从Java程序员的视角来看，他们操作的是对象的引用（类似于地址的抽象），而不是直接操作内存地址
> - 因此，可以说变量在概念上与值和地址都相关，但具体取决于我们如何定义和使用它们。在高级编程中，我们主要关注变量的值，而在需要直接操作内存或进行底层优化时，我们才会关注变量的地址
>
> 
>
> *变量就是一个存储数据的时候当前数据所在的内存地址的名字而已*。  *变量,其实是内存地址的一个抽像名字*
>
> 从本质上讲，变量就是在程序中保存用户数据的一块内存空间，而变量名就是这块内存空间的地址;  通过变量名，程序员可以方便地引用和操作存储在内存中的数据。变量的使用解决了直接通过内存地址访问数据的问题，因为内存地址难以记忆且随机分配，而变量名则提供了一个更易于理解和使用的标识符
>
> 
>
> 变量名 实际上是指向内存中特定位置的指针，它使得程序员可以通过这个名字来读写数据，而不需要直接操作内存地址; 
>
> 
>
> 此外，变量的类型和作用域决定了其在内存中的存储位置和可访问性。例如，在[C语言](https://www.baidu.com/s?sa=re_dqa_generate&wd=C语言&rsv_pq=9fc5485002ed98dc&oq=变量是内存地址的名字&rsv_t=71f5GWu/iC5ZNXtdG67lZ+b9NH9VY2+kqGWNwfNtMf1EWmxHe04n4tJSaOc&tn=baidu&ie=utf-8)中，变量可以根据其作用域分为[局部变量](https://www.baidu.com/s?sa=re_dqa_generate&wd=局部变量&rsv_pq=9fc5485002ed98dc&oq=变量是内存地址的名字&rsv_t=71f5GWu/iC5ZNXtdG67lZ+b9NH9VY2+kqGWNwfNtMf1EWmxHe04n4tJSaOc&tn=baidu&ie=utf-8)和[全局变量](https://www.baidu.com/s?sa=re_dqa_generate&wd=全局变量&rsv_pq=9fc5485002ed98dc&oq=变量是内存地址的名字&rsv_t=71f5GWu/iC5ZNXtdG67lZ+b9NH9VY2+kqGWNwfNtMf1EWmxHe04n4tJSaOc&tn=baidu&ie=utf-8)，根据存储方式可以分为[静态存储](https://www.baidu.com/s?sa=re_dqa_generate&wd=静态存储&rsv_pq=9fc5485002ed98dc&oq=变量是内存地址的名字&rsv_t=71f5GWu/iC5ZNXtdG67lZ+b9NH9VY2+kqGWNwfNtMf1EWmxHe04n4tJSaOc&tn=baidu&ie=utf-8)和[动态存储](https://www.baidu.com/s?sa=re_dqa_generate&wd=动态存储&rsv_pq=9fc5485002ed98dc&oq=变量是内存地址的名字&rsv_t=71f5GWu/iC5ZNXtdG67lZ+b9NH9VY2+kqGWNwfNtMf1EWmxHe04n4tJSaOc&tn=baidu&ie=utf-8)，这些分类进一步细化了变量的使用方式和生命周期。

==标识符==是程序中变量、函数、数组等的名字。标识符由字母（大写或小写）、数字和下划线组成，但第一个字符必须是字母或下划线，不能是数字。 

- ‌**定义方式**‌：普通常量（直接常量或字面常量）包括整型常量、实型常量和字符常量，它们在代码中直接给出具体的数值或字符。例如，整型常量如12、0、-3，实型常量如4.6、-1.23，字符常量如‘a’、‘b’。而符号常量是通过预处理指令`#define`定义的，它使用一个标识符来表示一个常量值，一旦定义，程序中所有出现该标识符的地方都将被替换为该常量值。例如，`#define PI 3.14159`定义了一个符号常量PI，其值为3.14159‌12。
- ‌**使用方式**‌：普通常量在代码中直接使用，而符号常量的使用方式是在定义之后，通过标识符（在这个例子中是PI）来引用该常量值。符号常量的一个重要优点是，如果需要在程序的多个地方改变这个常量的值，只需要修改定义处，而无需在每个使用的地方进行修改，这被称为“一改全改”‌3。
- ‌**内存占用情况**‌：==符号常量不占用内存空间==，因为在编译时，编译器会将符号常量的所有实例替换为定义的值。这意味着符号常量在内存中没有独立的存储位置，而是直接由其定义的值替代。相比之下，普通常量在内存中有其具体的存储位置，其值在程序运行期间不能改变‌3。

总的来说，符号常量提供了一种更灵活且易于管理的方式来定义和使用常量值，特别是在需要频繁修改常量值的情况下。同时，通过预处理指令的定义方式，符号常量能够在编译时进行优化，有助于提高代码的可读性和可维护性‌

```c
    int temp;
    printf("In swap,互换前：x=%d,y=%d\n", *x, *y);

    *x = *y;
    *y = temp;
```

```c
#include <stdio.h>
#include <stdarg.h>
int sum(int n, ...);
int sum(int n, ...) {
    int i, sum = 0;
    //定义一个字符指针，对它进行计算
    va_list vap;        //用va_list 定义参数列表
    va_start(vap, n);   //初始化参数列表，n第一个参数
    for(int i = 0; i < n; i++) {
        sum = sum + va_arg(vap, int);   //获取后面每一个参数的值
    }
    va_end(vap);        //关闭参数列表
    return sum;
}

int main() {
    int result;
    result = sum(3, 1, 2, 3);
    printf("result = %d\n", result);

    result = sum(4, 5, 4, 2, 8);
    printf("result = %d\n", result);
```

**定义和声明** 

- ==变量声明==是指在程序中声明一个变量，并指定它的名称和类型，但并不为它分配具体的值。变量声明告诉[编译器](https://so.csdn.net/so/search?q=编译器&spm=1001.2101.3001.7020)或解释器有一个变量存在，可以在程序的其他部分使用它
  - 声明告诉编译器变量的类型以及变量的名称。
  - 它不分配内存空间给变量（除了在某些特殊情况下，如外部或静态变量的声明）。
  - 声明可以多次出现在同一个程序中，但必须在变量被使用之前。
  - 声明通常出现在函数外部（全局作用域）或函数内部（局部作用域）的顶部。
- 变量定义是指在程序中给变量分配具体的值。它为变量分配内存，并初始化它的值。变量定义可以在声明的同时完成，也可以在稍后的代码中进行
  - 定义包含变量的声明，并为变量分配内存空间。
  - 它确保变量有一个确定的值（除非它被显式地初始化为不确定的值，如未初始化的局部变量）。
  - 一个变量只能在一个地方定义。
  - 定义通常伴随着一个初始值（尽管这不是必须的，但对于局部变量来说，未初始化的局部变量会有不确定的值）。

#### 指向数组的指针

指针和数组关系密切，但数组绝不是指针

- ==数组名==其实是**数组第一个元素的地址**
- ==指向数组的指针==： 用指针指向数组； 下图中的==语句1 等价于 语句2== 
  - `char *p;  p=a; 或 p=&a[0]` 用指针指向数组第一个元素的地址

- **指针的运算**
  - 下标法、指针法
  - 不是将地址加1，而是**指向数组的下一个元素**
  
- ==用指针定义字符串==，用下标法读取每个元素

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int a ;                 // 定义变量a
    int *p = &a;            // 定义指针变量，指向a变量
    
    printf("a = %d\n", a);			   //值：	   0
    printf("a = %x\n", &a);			   //地址：  22fe4c
```

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int i, num;
    int count = 0;
    int *ptr = NULL;    //初始化化为NULL

    do {
        printf("请输入一个整数(-1表示结束):");
        scanf("%d", &num);
        count++;
        ptr = (int *)realloc(ptr, count * sizeof(int));
        if(ptr == NULL) {
            exit(1);
        }
        ptr[count - 1] = num;   //num存到最新分配的空间
    } while(num != -1);

    printf("输入的整数分别是:");
    for(int i = 0; i < count; i++) {
        printf("%d ", ptr[i]);
    }
    putchar('\n');
    free(ptr);

}
```

#  头文件

[C 头文件](https://www.runoob.com/cprogramming/c-header-files.html) 

头文件是扩展名为 `.h` 的文件，包含了 C `函数声明和宏定义`，被多个源文件中引用共享。有两种类型的头文件：程序员编写的头文件和编译器自带的头文件。	

使用头文件，需要使用 C 预处理指令 `#include` 来引用它

`A simple practice in C` 或 C++ 程序中，建议把所有的==常量、宏、系统全局变量和函数原型==写在头文件中，在需要的时候随时引用这些头文件。

1. 引用系统头文件： `#include <file>`
   1. 引用的是编译器的==类库路径==里面的头文件
2. 引用用户头文件： `#include "file"` 
   1. 引用的是==程序目录==的相对路径中的头文件，如果在程序目录没有找到引用的头文件, 则到编译器的类库路径的目录下找该头文件

## 只引用一次头文件

如果一个头文件被引用两次，编译器会处理两次头文件的内容，这将产生错误。为了防止这种情况，标准的做法是把文件的整个内容放在条件编译语句中
