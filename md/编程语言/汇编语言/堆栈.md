# 栈帧的基准位置

[栈帧的基准位置_百度搜索](https://www.baidu.com/s?ie=UTF-8&wd=%E6%A0%88%E5%B8%A7%E7%9A%84%E5%9F%BA%E5%87%86%E4%BD%8D%E7%BD%AE)  

栈帧的基准位置由寄存器 EBP（基址指针）确定，它==固定指向当前栈帧的底部==（高地址端）

> 函数调用 时，当前函数使用一块栈空间，这一块空间称为：栈帧，Stack Frame。 一个函数的栈帧严格包含: [栈帧](https://blog.csdn.net/That_Assassin/article/details/164229246)  

### EBP 的作用

1. 稳定基准：EBP 在函数生命周期内保持不变，所有参数和局部变量都通过它加偏移量访问，不受 ESP 随入栈/出栈变化的影响。
2. 定位规则：参数在 EBP 正偏移处（如 `[ebp+8]`、`[ebp+12]`），局部变量在负偏移处（如 `[ebp-4]`）。
3. 建立过程：函数入口执行 `push ebp` 保存旧值，再 `mov ebp, esp` 将当前栈顶设为新基准。

### 与 ESP 的分工

- EBP：静态锚点，指向栈帧底部，作为寻址原点。
- ESP：动态指针，始终指向栈顶，随 push/pop 移动。

> 注意：EBP 指向当前栈帧底部，而非系统栈底；栈向下增长，故 EBP 在高地址、ESP 在低地址。

# BP寄存器

BP是基址指针寄存器，主要用来==定位栈帧里的数据==，比如函数参数和局部变量。它和SP配合，一个当“锚点”，一个当“浮标”，这样函数调用时才能稳定地找到栈上的数据。

### BP和SP的分工

1. SP（栈顶指针）：始终指向栈顶，PUSH/POP时自动变化，就像栈的“活动边界”。
2. BP（基址指针）：在函数执行期间基本固定，指向当前栈帧的基准位置，通过`[bp+偏移]`访问参数和局部变量。

### 典型函数调用中的BP用法

函数开头通常有段“模板代码”：

```assembly
push bp        ; 保存调用者的BP
mov bp, sp     ; 让BP指向当前栈帧基址
sub sp, N      ; 为局部变量预留空间
```

执行后，栈帧布局清晰可见：
- `[bp+4]`、`[bp+6]`：访问传入的参数（16位环境下）
- `[bp-2]`、`[bp-4]`：访问局部变量
- 函数结束时用 `mov sp, bp` 和 `pop bp` 恢复现场

### 为什么不用SP直接寻址

SP频繁变化，用`[sp+偏移]`访问数据不可靠，CPU硬件层面也不支持这种寻方式。BP固定不变，偏移量在编译期就能确定，所以它才是访问栈内数据的稳定基准。

### 注意

- BP默认与SS段寄存器搭配，访问栈段数据；BX默认与DS搭配，访问数据段。
- 64位模式下BP对应RBP，编译器优化（`-fomit-frame-pointer`）可能省略帧指针，直接用RSP+偏移访问。

# SP和BP

1. ‌**SP（Stack Pointer，堆栈指针）**‌：始终指向‌**栈顶**‌，是CPU自动维护的。`push`操作时SP自动减小，`pop`操作时自动增大，函数调用时保存返回地址、局部变量都靠它动态调整。
2. ‌**BP（Base Pointer，基址指针）**‌：指向‌**栈基址**‌，即当前栈帧的固定基准点。函数调用时，BP被设为进入函数那一刻的SP值，之后通过`[BP+偏移]`来访问参数和局部变量，不受SP动态变化影响，方便调试时栈回溯。‌‌

> 简单理解：SP就像不断移动的栈顶指针，==BP是固定在栈底的锚点==。函数参数和局部变量通过BP加偏移来定位，这样即使SP因压栈出栈来回动，也不影响访问
