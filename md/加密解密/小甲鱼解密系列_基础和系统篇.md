- 句柄： 常被视为一种==智能指针==，用于引用其他系统管理的内存块或对象‌
  - 句柄是一个标识符，用来标识对象或项目，通常是一个编号，用于管理控制计算机资源

- 匈牙利命名法
- 回调函数： `Don't call me,  I'll call you`， 设定好的函数： 回调函数不让我们自己程序调用，而是windows程序去调用,通过消息机制实现
  - 例如：要早起，不用不停的看闹钟几点了，到时间，闹钟会叫你起来; 叫醒程序作为参数传给闹钟，到点执行叫醒程序
  - **回调函数不是自己调自己，而是由其他模块或系统在特定条件下调用**
  - 回调函数作为参数传递给另一个函数，并`在被调用函数执行完毕后`被调用。回调函数通常用于事件处理、异步编程和处理各种操作系统和框架的API.
  - 回调函数是指一段以参数的形式传递给其他代码的可执行代码。具体来说，回调函数是由使用者自己定义一个函数，然后将这个函数的指针作为参数传递给另一个函数。当特定事件或条件发生时，这个被传递的函数（即回调函数）会被外部的函数调用执行‌.

## windows消息机制

[Windows消息机制](https://baijiahao.baidu.com/s?id=1786033574975159496&wfr=spider&for=pc)    [windows消息机制](https://www.cnblogs.com/csqtech/p/5576098.html)  [Windows 消息处理机制与事件驱动](https://www.cnblogs.com/jeemhu/archive/2009/05/09/1453297.html)

- Windows中用于处理用户输入、系统事件以及应用程序间通信的一种机制。它通过‌[消息队列](https://www.baidu.com/s?wd=消息队列&usm=3&ie=utf-8&rsv_pq=9152441300d0111f&oq=windows消息机制&rsv_t=32c2w7KJhDV%2FG6e4Kir5qcjaaurn7uEoGbgodRvGPFcIb1nHFay7nvy3DrA&sa=re_dqa_generate)和‌[消息循环](https://www.baidu.com/s?wd=消息循环&usm=3&ie=utf-8&rsv_pq=9152441300d0111f&oq=windows消息机制&rsv_t=32c2w7KJhDV%2FG6e4Kir5qcjaaurn7uEoGbgodRvGPFcIb1nHFay7nvy3DrA&sa=re_dqa_generate)来实现，允许应用程序以==事件驱动==的方式响应用户操作和系统事件
- 消息机制的概念: `消息、消息队列、消息循环`
- 消息的来源和类型
  - 输入消息：由用户的键盘和鼠标操作产生
  - 控制消息：由应用程序内部的事件触发，如窗口大小改变等
  - 系统消息：由操作系统产生，如定时器超时等
  - 用户消息：通过发送自定义消息进行应用程序间的通信。
- 消息的处理过程
  - 捕获事件：Windows监控用户的输入和系统的变化，将事件转化为消息
  - 放入消息队列：将消息放入相应的线程的消息队列中等待处理
  - 消息循环：应用程序通过不断检查消息队列中的消息，并调用相应的处理函数来响应
  - 处理消息：根据消息的类型和内容，应用程序执行相应的操作

### pe结构中Data Directory和SECTION table关系

[pe结构中Data Directory和SECTION table关系_百度搜索](https://www.baidu.com/s?ie=utf-8&f=8&rsv_bp=1&tn=baidu&wd=pe%E7%BB%93%E6%9E%84%E4%B8%ADData%20Directory%E5%92%8CSECTION%20table%E5%85%B3%E7%B3%BB&oq=Data%2520Directory%25E5%2592%258CS%2526gt%253B%2526lt%253BTION%2520table%25E5%2585%25B3%25E7%25B3%25BB&rsv_pq=d86f984600019365&rsv_t=c952h%2FGPPHHo1vNsju1V4aKE58nnAoSzlCDq9d5f66DSETkS5SA1l8rgnOI&rqlang=cn&rsv_enter=1&rsv_dl=tb&rsv_btype=t&inputT=4397&rsv_sug3=37&rsv_sug1=8&rsv_sug7=100&rsv_sug2=0&rsv_sug4=48834)	

在讨论PE（Portable Executable）文件结构时，特别是其内部的数据目录（Data Directory）和SECTION table之间的关系，我们需要先了解这些组成部分的基本概念和功能。

1. **PE文件结构**
    PE文件是一种用于Windows平台上的可执行文件格式。PE文件的结构大致可以分为以下几个部分：
  1. DOS Header：位于文件的开始，用于兼容DOS操作系统。
  2. NT Header：紧随DOS Header之后，包含了PE文件的关键信息，如签名、机器类型、日期时间等。
  3. Optional Header：位于NT Header中，提供了关于程序如何被加载到内存中的详细信息。
  4. Sections Headers：在Optional Header之后，包含了一个或多个Section Headers，描述了文件中各个节（section）的信息，如节名、节的大小、在文件中的偏移等。
  5. Sections：紧随Section Headers之后，包含了实际的二进制代码、数据和其他资源。


2. Data Directory
    Data Directory位于Optional Header中，它是一个数组，每个条目包含两个成员：一个RVA（Relative Virtual Address）和一个Size。这些条目指向文件中特定的数据表或结构，例如导入表、导出表、资源表等。Data Directory的存在是为了提供一种快速查找这些表的方法，而不需要解析整个Optional Header或Section Headers。

3. Relationship Between Data Directory and SECTION Table
    Data Directory和SECTION table之间的关系主要体现在以下几个方面：
  1. 定位数据：Data Directory中的每个条目通过RVA指向特定的数据结构或表。这些数据结构或表通常存储在某个Section中。例如，一个条目可能指向导出表（Export Table），而这个导出表实际上存储在某个特定的Section中（通常是.edata节）。
  2. 间接访问：通过Data Directory，操作系统或加载器可以快速定位到需要的数据结构，而无需解析整个PE文件的Sections Headers。这使得访问这些结构更加高效。
  3. 内存布局：在内存中，PE文件被加载时，Sections被映射到虚拟地址空间的不同位置。Data Directory中的RVA指向的是这些节在内存中的虚拟地址。因此，虽然Data Directory指向的是节中的数据结构，但这些数据结构实际上是通过RVA在内存中访问的。


**示例:** 
假设我们想要访问PE文件中的导出表（Export Table），我们可以这样做：

- 查看Data Directory中的导出表条目，获取其RVA和大小。
- 将RVA转换为实际的内存地址（如果已经加载到内存中）。
- 访问该地址处的内存区域，即为我们需要的导出表。

这种方式使得PE文件的内部结构更加灵活和高效，尤其是在处理大型程序时。通过Data Directory和Sections的配合使用，可以有效地管理和访问各种数据和资源。

  - 实际装入的地址（20003000h）
  - `需要修正的地址 + (实际 - 建议)`

- 哪些信息应该被保存在重定位表中
  - **PE 文件的重定位表（Base Relocation Table）中保存的就是文件中所有==需要进行重定位修正==的代码的地址**

- PE 文件中的资源是按照 **资源类型 -> 标识符  ->资源ID -> 资源代码页** 的3层树型目录结构来组织资源的，通过层层索引才能够进入相应的子目录找到正确的资源
- 每一层都是由 `IMAGE_RESOURCE_DIRECTORY 结构（深灰色的）`和紧跟其后的数个`IMAGE_RESOURCE_DIRECTORY_ENTRY 结构（浅灰色的）`组成

| ------------------------------------------------------------ | ------------------------------------------------------------ |
| ![](./小甲鱼解密系列_基础和系统篇.assets/Snipaste_2025-04-16_14-11-21.jpg) |                                                              |

- `IMAGE_RESOURCE_DIRECTORY STRUCT`             16 字节（dw、dw、w、w、w、w）
- `IMAGE_RESOURCE_DIRECTORY_ENTRY STRUCT`        8字节（dw、dw）
  - Name 字段定义的是目录项的==名称或ID==。当结构用于第一层目录时，定义的是==资源类型==；当结构定义于第二层目录时，定义的是资源的==名称==；当结构用于第三层目录时，定义的是==代码页编号==
    - **当最高位为 0 的时候**，表示字段的值作为 ID 使用
  - OffsetToData ：DWORD ， 目录项指针
    - **当最高位为 1 时，**低位数据指向下一层目录块的真实地址 
      - 下一层地址是： OffsetToData低位 + 资源区块开始的地址
    - **当最高位为 0 时，**指针指向 `IMAGE_RESOURCE_DATA_ENTRY` 结构
- `IMAGE_RESOURCE_DATA_ENTRY`                   16 字节（dw、dw、dw、dw）
  - 结构里的 `Offset To Data`是虚拟地址，算出物理地址，就是数据所在的位置。
